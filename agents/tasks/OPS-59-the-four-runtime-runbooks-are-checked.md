## Why

The runbooks for a Claude Code scheduled task, a Claude Tag routine, Managed Agents and an Agent SDK runner were read against the vendor pages only by the worker that wrote each one, and each says it is not yet independently verified. An engineer follows these step by step inside a customer's org, so a wrong menu path, header value or permission default costs real time or opens real access. You are the second reader: you did not write them, and you treat every sentence as untrusted until the page says it.

## Done when

- The four runbooks are starter-kit/runbooks/claude-code-scheduled-task.md, claude-tag-routine.md, managed-agents.md and agent-sdk-runner.md. Read starter-kit/runbooks/verification-log.md first, whole: its section 'How the check was done' is the method, and you follow it exactly (every numbered step, table row and factual product sentence is checked against the page it cites; a source tag is not proof; where the cited page does not support the claim, look on the vendor's own documentation; exact strings such as keys, menu paths, header values, endpoint URLs, setting names, CLI commands and defaults are compared character by character; rows that are our own design, such as hand-over lists and our recommendations, are not counted).
- You fetch each cited page yourself in this session. A claim is Confirmed only when you have read the sentence or sample on the page that supports it. Do not confirm from memory, from the runbook's own tag, or from another repo file. If a page cannot be fetched after two tries, the claims that rest on it are Unverified and the page is added to the log's section 'Sources that could not be read' with the date and what happened.
- Accepted vendor domains for these four runbooks: platform.claude.com, code.claude.com, claude.com (docs and connectors pages), support.claude.com, and github.com under the anthropics, anthropic-ai or modelcontextprotocol organisations. Blogs, forums and search snippets do not count.
- States, as the log defines them. Confirmed: the page supports the claim. Corrected: you changed the runbook to match the page, and the log row gives old wording and new wording. Unverified: no accepted page confirmed it, so the runbook carries the marker '**⚠ Unverified:**' and words the item as something to confirm at setup. Where two vendor pages disagree, the runbook carries '**⚠ Conflict:**' naming both, and the row is counted Unverified.
- Every existing '**⚠ Unverified:**' item in the four runbooks is tried again: if an accepted page now settles it, replace the marker with the statement and its source tag (add the page to 'Pages used' with the next free letter) and log it as Corrected; if not, it stays and is logged Unverified.
- Changes to a runbook are the smallest true change. No numbered step is added, removed or reordered, no level-2 heading changes, and no relative link target or anchor that other files could point at is renamed. If a correction pushes a file past the line limit its test sets, tighten wording elsewhere in the same file without dropping a fact.
- In each of the four runbooks the two sentences 'Checked 2026-11-16 by the author against the pages listed. Not yet independently verified: verification-log.md has no rows for this runbook.' are replaced by exactly: 'Checked 2026-11-16 by the author against the pages listed. Every claim was checked again on <YYYY-MM-DD> by a second reader; the results are in the [verification log](verification-log.md).' with the UTC date you finished that runbook's check. tests/test_runbooks_client_runtimes.py and tests/test_runbooks_hosted_runtimes.py are changed only where they pin the old sentence: they now require the new one, with the date matched by a pattern.
- verification-log.md gains, without changing any existing row: (a) one line under the header list, '- **Updated <date> (<this task id>):** sections for the four runtime runbooks were added by a second reader, <your model name and id>; their rows are in the summary table below.'; (b) one row per runbook in the summary table (Confirmed, Corrected, Unverified, Total); (c) one sentence added to 'How the check was done' naming the accepted domains for the runtime runbooks; (d) one section per runbook, headed '## <file name> (<this task id>)', placed before '## Sources that could not be read', each a table with the same five columns the existing sections use (Line or step | Claim | State | Source URL | Old wording → new wording (corrections)), one row per claim checked.
- Each summary-table row's counts equal the number of rows of each state in that runbook's section, and Total is their sum. Every Confirmed or Corrected row has a source: an https URL on an accepted domain, or 'repo: <path>' for a statement about this repository. Every Corrected row has the old and new wording.
- A new test file tests/test_runbook_verification_log.py holds a list VERIFIED_RUNBOOKS with these four file names and, for each: the log has a level-2 section whose heading starts with the file name; the section's table has at least 15 rows; every row's state is Confirmed, Corrected or Unverified; every Confirmed or Corrected row has an accepted https URL or a 'repo:' source whose path exists; every Corrected row has non-empty old-to-new text; the summary table has a row for the file whose four numbers match the section; the runbook does not contain 'Not yet independently verified' and does contain the new sentence with a link to verification-log.md.
