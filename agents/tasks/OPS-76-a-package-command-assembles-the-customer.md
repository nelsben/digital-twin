## Why

The last mile of epic #254: an evaluated skill or agent is only useful once it is published to the right people in the customer's org. The kit already has runbooks for every step and the backlog lists them per persona; this card packages what was built and turns those steps into one ordered checklist per customer, with deployment and its check recorded, and never puts a customer credential in the repo.

## Done when

- Read first: partner-kit/docs/design.md sections 3, 8 and 8a, build.py and the record command OPS-75 added, the backlog.json of both samples, starter-kit/runbooks/identity-devices-publishing.md (section 6 and the Team plan section), managed-agents.md (including Self-hosted), claude-tag-routine.md, claude-code-scheduled-task.md, agent-sdk-runner.md and the connector runbooks the samples' backlogs link, .claude-plugin/marketplace.json for the marketplace shape, and docs/compendium/16-oob-skills-and-references.md point 5. Read only outside scope.
- PACKAGE. New command `cli.py package <customer-dir> [--include-drafts]`, where <customer-dir> holds customer-profile.json and personas/. It reads every persona's build/build.json and writes engagements/<customer>/build/marketplace/: .claude-plugin/marketplace.json (same shape as the repo's own; name from customer-profile.json if it names one, otherwise '<customer id>-twins'; one entry per role plugin) and plugins/<plugin_name>/ copied from each persona's build/plugin/. Agent, routine, scheduled and SDK artifacts go to engagements/<customer>/build/bundles/<persona-id>/<task-id>/ with their skill folder beside them. Only artifacts at evals-passing or above are packaged, and a role plugin is packaged only when every skill in it is; package then records packaged for each. With --include-drafts it writes to build/marketplace-draft/ and build/bundles-draft/ instead, includes drafted artifacts, records nothing, and every plugin description there starts 'DRAFT, not evaluated:'. A persona with nothing to package is listed on stderr with the reason. Two runs give the same bytes. The partner kit is never packaged.
- DEPLOY CHECKLIST. package also writes engagements/<customer>/build/deploy.md (written with or without --include-drafts, because it depends on the plan, not on eval status). It is an ordered view of the deployment tasks already in each persona's backlog.json, not new task wording: org settings and data policy, identity and groups, connectors and each tool permission, publishing the marketplace to the right groups (by persona_plan.distribution: group-targeted on Enterprise, everyone on Team, manual as per-person install), each hosted agent, routine and scheduled task with its bundle path, the governance hook, then each runbook's check-it-worked line and hand-over. Each step is a checkbox with the backlog task id, owner role and name, the runbook link with anchor and the package path it uses. Credentials appear only as environment-variable names. A step whose backlog task is gated by a blocker or open question says so. Design 8a names the order and the rule that deploy.md never adds a step the backlog does not have; a missing step is reported in the hand-back instead.
- RECORD, HIGHER STATUSES. record now accepts packaged -> deployed (--by the admin's name, --evidence a note under build/evidence/<artifact-id>/ saying where it was published or created: surface, group or channel, agent id placeholder allowed only as a name, no secret) and deployed -> verified (--evidence a note with the runbook's check-it-worked result). packaged is set only by package. One status at a time, never backwards, as OPS-75 built.
- NO SECRETS. A test scans every file under each sample's build/ folders (persona and customer) for keys, tokens, passwords, org or tenant ids and instance URLs, using the patterns OPS-74's test uses, and fails on any. The skill building-twin-artifacts gains a short section on packaging and deployment: the admin runs deploy.md in the customer's org; the consultant records; credentials live in the customer's secret store, never in the engagement folder.
- SAMPLES. Run package on both fictional samples without and with --include-drafts. Without it, nothing is packaged (no artifact is evals-passing) and the stderr lines say why; with it, the draft marketplace and bundles are written. Both deploy.md files are written. Nothing is recorded above drafted. Everything stays fictional; completeness lines do not change.
- Docs in the same change: design.md 8a and section 3's layout (customer build folder, package, deploy.md, the higher statuses), the plugin README, partner-kit/README.md, and docs/playbook/05-persona-card-workflow.md gains a short 'Build, evaluate and deploy' section that links the design and the skill rather than copying them.
