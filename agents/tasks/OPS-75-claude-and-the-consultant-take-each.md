- RECORD. New command `cli.py record <persona-dir> <artifact-id> --status <status> --evidence <file> --by <name> [--pass-mark <percent> --approved-by <name>]`. It moves an artifact one status at a time and never backwards, and writes nothing on a refusal. drafted -> evals-passing needs: check passes for that artifact; an evidence file under <persona-dir>/build/evidence/<artifact-id>/ that is either skill-creator's benchmark output or the `claude plugin eval` JSON report, in the shape the two pages above give (name the fields you read in the design and the hand-back; if a page does not give a machine-readable shape, accept that tool's file only after a test fixture shows its real shape, and say so); a with-skill run whose pass rate meets the pass mark (default 100% of cases; a lower mark needs --approved-by, recorded); and a without-skill baseline in the same evidence, which the record stores beside the with-skill rate. The higher statuses (packaged, deployed, verified) are refused with 'Next: ' pointing to the package command, which OPS-76 adds. build.json gains per artifact a history list of {status, by, evidence, pass_rate, baseline_rate, pass_mark, approved_by}; no timestamps, so the file stays reproducible; `build` keeps the history and statuses.
