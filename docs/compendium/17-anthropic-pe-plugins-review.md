# 17 — Review of Anthropic's private-equity and financial-analysis plugins

Page [16](16-oob-skills-and-references.md) recommends starting the private-equity twin from two of Anthropic's plugins: `financial-analysis` and `private-equity`, both in [anthropics/financial-services](https://github.com/anthropics/financial-services). This page is the review that has to happen before a deal team uses them. It lists every part of each plugin, follows every data flow out of the laptop, gives each skill a verdict, and says how to keep a reviewed copy fixed.

**What was reviewed.** Commit [`3e32c2287dcb637c184c01cc0ad82d6af7e9bb0f`](https://github.com/anthropics/financial-services/commit/3e32c2287dcb637c184c01cc0ad82d6af7e9bb0f) on `main` (2026-11-12), read on 2026-11-14 from a clone of the repo. Both plugins are at version `0.1.2` in their `plugin.json`. The last commit that touched either plugin folder is [`6056506`](https://github.com/anthropics/financial-services/commit/60565064557ca77b12f62aa7877f365d111c129d) (2026-10-28). The licence is Apache-2.0 ([LICENSE](https://github.com/anthropics/financial-services/blob/3e32c2287dcb637c184c01cc0ad82d6af7e9bb0f/LICENSE)). Every file link below is pinned to the reviewed commit.

Verdicts use page 16's terms: **adopt** (use as shipped), **adapt** (change it, and we say what), **skip** (don't use, and we say why). All verdicts are (Our recommendation).

## The short answer

- **Neither plugin has agents or hooks.** Both `hooks/hooks.json` files are empty (`{"hooks": {}}`), and neither plugin has an `agents/` folder. The named agents in the repo are separate plugins under `plugins/agent-plugins/` and are outside this review.
- **`private-equity` brings no connectors.** Its `.mcp.json` is empty.
- **`financial-analysis` brings 12 connectors, all third-party.** Installing it as shipped registers 12 remote MCP servers (market data vendors, PitchBook, Chronograph, Box, Egnyte). None is Anthropic's. **None is acceptable by default in the private-equity ZDR org**, because a query to a data vendor reveals what the deal team is looking at.
- **Three skills reach the web or a mailbox.** `dcf-model` uses web search and fetch, `deal-sourcing` uses web search and reads and drafts in Gmail and Slack, and `3-statement-model` points at SEC EDGAR. The kit's private-equity settings already deny WebSearch and WebFetch ([`pe-zdr.managed-settings.json`](../../starter-kit/settings/pe-zdr.managed-settings.json)), so these steps would fail in the org. They are removed or rewritten in our copy.
- **T1 and T2 get little from layering.** No upstream skill writes a company brief from Salesforce or a CRM update from a meeting. The value is in the backlog: CIM screening (T4), call prep (T5) and IC memo sections (T6).
- **Pin by vendoring.** Copy the reviewed folders into `digital-twin-kit`, with the connectors removed. Listing the upstream marketplace can't be pinned to a commit, because its name is reserved (section 5).

## 3. Where the data goes: connectors and external tools

**How a connector call flows in Claude Code** (from compendium [10](10-sensitive-data.md) and [11](11-connectors.md)):

1. The tool call's arguments go to the vendor's server: a company name, a ticker or a question. **⚠ Unverified:** whether a plugin's remote server is called from the laptop or from Anthropic. Compendium 11 says claude.ai connectors call from Anthropic's IP range, but no page we read says the same for a plugin's `.mcp.json` server in Claude Code.
2. The vendor's answer enters the conversation and is sent to Anthropic. ZDR covers this only in Claude Code on a ZDR sign-in, not in Cowork or chat.
3. The vendor keeps whatever its own terms allow. **⚠ Unverified:** for all 12 vendors, what they log or retain about queries. Anthropic doesn't audit any MCP server ([managed MCP](https://code.claude.com/docs/en/managed-mcp)).

**The MNPI exposure is the query itself.** Asking a vendor about a private company, or pulling comps for a public one, tells that vendor what the firm is looking at. For a live deal that is MNPI, whatever the vendor sends back. The `.mcp.json` gives only URLs and no sign-in details. The README says "MCP access may require a subscription or API key from the provider". **⚠ Unverified:** each vendor's identity model (per user or shared).

## 5. How to pin a reviewed copy

**Option A: list the upstream marketplace.** Add `anthropics/financial-services` under `strictKnownMarketplaces` and `extraKnownMarketplaces`, and enable the two plugins.

- An allowlist entry for GitHub takes an optional `ref`, which must match exactly ([plugins for your organization](https://code.claude.com/docs/en/plugins/org)).
- A marketplace `ref` can be a full commit SHA (Claude Code v2.1.324 or later), but that "is refused for a marketplace with a reserved name". `claude-for-financial-services` is on the reserved list ([marketplace reference](https://code.claude.com/docs/en/plugins/marketplace-reference)). The repo has no tags. **So the upstream marketplace can only follow a branch, in practice `main`.**
- Its plugins use relative paths, so they move with the marketplace. A change reaches installed users when a plugin's `version` goes up, and the repo's CI requires a version bump on every plugin change ([CLAUDE.md](https://github.com/anthropics/financial-services/blob/3e32c2287dcb637c184c01cc0ad82d6af7e9bb0f/CLAUDE.md), [version-bump.yml](https://github.com/anthropics/financial-services/blob/3e32c2287dcb637c184c01cc0ad82d6af7e9bb0f/.github/workflows/version-bump.yml)). Turning `autoUpdate` off only delays the change.
- We could not change anything. The 12 connectors and `deal-sourcing` would arrive as shipped, and every other plugin in that marketplace would need `false` in `enabledPlugins`.
- It is a second marketplace, which design section 8 rules out.
- **For:** no upkeep; upstream fixes arrive by themselves. **Against:** unreviewed changes arrive by themselves too.

**Option B: one plugin entry with a `git-subdir` source and a `sha`.** This pins one folder of the upstream repo from inside `digital-twin-kit`. It keeps one marketplace and an exact commit, but it can't change files. Both plugins need changes, so it doesn't fit here.

**Option C: vendor into `digital-twin-kit` (Our recommendation).** Copy the two plugin folders at the reviewed commit into `starter-kit/plugins/`, make the changes in sections 1 and 2, and publish them from our one marketplace.

- Record the upstream repo, path and full SHA in the copy, for example in an `UPSTREAM.md` beside `plugin.json`.
- Keep the Apache-2.0 licence. Section 4(b) of the [licence](https://github.com/anthropics/financial-services/blob/3e32c2287dcb637c184c01cc0ad82d6af7e9bb0f/LICENSE) requires "prominent notices stating that You changed the files" on every modified file.
- Delete the `.mcp.json` from the copy. Also restrict MCP in managed settings: `allowManagedMcpServersOnly` with an `allowedMcpServers` list. That list also checks servers that plugins add ([managed MCP](https://code.claude.com/docs/en/managed-mcp)). The kit's `pe-zdr` baseline has no MCP list today, so adding one is a follow-up.
- The copy has to pass the kit's tests: skill bodies under 500 lines and only `name` and `description` in the frontmatter.
- **For:** users get exactly the files we reviewed, plus our changes, through one marketplace, under our tests. **Against:** we merge upstream changes by hand, and our copy falls behind until we do.

**When to review again.**

- Any upstream commit that touches `plugins/vertical-plugins/private-equity/` or `plugins/vertical-plugins/financial-analysis/` after `3e32c22`. A raised `version` in either `plugin.json` is the simplest signal, because the repo's CI requires it.
- At once, whatever the size of the change: a new connector, any hook, an agent, a script that uses the network, or a skill that asks for web, mail or a write tool.
- When Anthropic changes what ZDR covers (compendium 10), or when this firm adds a connector.

The skill engineer checks every month, reads the diff against this page, carries changes into the copy, and updates the recorded SHA and this page's commit. A reviewer other than the author signs it off (design section 8). Our copy never changes by itself, so a missed check means drift, not exposure.
