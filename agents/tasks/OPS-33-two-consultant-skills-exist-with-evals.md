## Why

Going from an interview to a persona card is the one step of the workflow that is language work, so it is a skill a consultant drives with Claude, not a script. The kit's authoring guide requires evals before the skill text. The persona card is card.json (not the persona voice file in starter-kit/templates/persona, and not a task card); the customer profile is customer-profile.json.

## Done when

- Read first, whole: starter-kit/docs/authoring-skills.md, starter-kit/templates/skill/ (README, SKILL.md, both eval files), partner-kit/docs/design.md sections 2 to 6, partner-kit/plugins/twin-consultant/README.md, templates/interview-guide.md, templates/interview-notes.md, templates/card.json, templates/customer-profile.json, data/fields.json, the industry packs, and both fixtures (engagements/sample-pe and engagements/sample-team-cs: customer-profile.json, personas/*/card.json, personas/*/interviews/*.md). Fetch https://code.claude.com/docs/en/skills and use only what it documents for how a plugin skill refers to files in its own plugin folder; quote the sentence you relied on in the report. If it documents no such way, the skill tells Claude to find cli.py two folders above the skill folder.
- Order of work, as the authoring guide requires: write evals/evals.json and evals/trigger-evals.json for each skill before its SKILL.md, and commit them in a separate earlier commit so the order is visible in the history.
- Both skills live at partner-kit/plugins/twin-consultant/skills/<name>/ with SKILL.md, evals/evals.json, evals/trigger-evals.json, evals/files/ and references/ only where needed. Frontmatter holds name and description only; name equals the folder name; description is under 200 characters, third person, and says when to use it; body under 150 lines. Plain language throughout: none of the words tests/test_interview_kit.py bans in spoken text appear in anything the skill tells Claude to say to a customer.
- preparing-role-interviews. Input: the customer folder under engagements/, the role name, and who will be interviewed. It reads the customer profile if one exists, the industry pack named by the profile's industry (general when there is no profile), and any card.json already in the persona folder. It produces (a) the persona folder engagements/<customer>/personas/<persona-id>/ with interviews/ (persona id is kebab-case, derived from the role name, confirmed with the consultant), (b) one notes file per interviewee at interviews/<yyyy-mm-dd>-<who>.md copied from templates/interview-notes.md with its header filled, where <who> is a role label and never a real name unless the consultant says to use it, and (c) a short tailored plan printed to the consultant: which questions of the guide to ask this person (all P and F question ids stay as they are; none is renumbered or reworded in the files), which are already answered in the card and can be confirmed instead of asked, and the pack's typical tasks turned into prompts ('Do you do anything like <task name>?'). It never writes card.json and never invents an answer. If the customer folder or the role name is missing, it asks.
- filling-persona-cards. Input: a persona folder with one or more interview-notes files. It creates card.json from templates/card.json when none exists, otherwise updates the one there without discarding fields that already have an answered provenance. For each field in data/fields.json it fills the value only from what the notes say under the question ids that the catalogue's asked_by lists for that field, and writes the provenance entry: status answered with source interviews/<file>#<question id>; status default with the pack or compendium page as source when the value comes from a pack default; status assumed with an owner when it is the consultant's guess; status open with owner and due, value null, plus an open_questions entry naming the tasks it blocks, when the notes do not say. A sponsor goal heard only from the interviewee (question P3) is assumed, owner the sponsor, until the sponsor confirms it. Two interviewees who disagree are not averaged: the field is open with both answers quoted in the open question. It never copies a figure or name that is not in the notes.
- filling-persona-cards also covers the customer profile: when ../../customer-profile.json is missing it says so and offers to create it from templates/customer-profile.json and the engagement's discovery answers, with provenance citing discovery question ids; it does not guess plan, identity, device or compliance answers. For anything under engagements/sample-* it sets fictional true and uses invented names only.
- After writing, filling-persona-cards runs the validate command, reads each '<record>:<path>: <message>. Next: <fix>' line, fixes what it can from the notes, and stops when validation passes or what is left needs a person. It ends with: the completeness percentage, the fields still open or assumed with their owners, and the next step (level the card, which is another skill; do not run it here). It names the persona card term collision once in its body so Claude does not edit the persona voice file or a task card.
- Evals for preparing-role-interviews: at least four cases in evals.json (a normal case on the private-equity fixture's customer for a new role; a case where a card already exists so some questions are confirm-only; a missing-input case where no role is named; a should-not-trigger near miss such as a request to write the persona voice file) and at least eight trigger queries, half should_trigger false, the negatives being near misses (persona voice, a task card, a discovery questionnaire, running the validator).
- Evals for filling-persona-cards: at least five cases (the Team fixture's two notes files, expected to give a card that validates at the completeness the fixture has; the private-equity fixture's notes, expected to leave the same items open as its card.json does; a notes file with a required answer missing, expected to give an open field with owner and due and no invented value; two notes files that disagree on one field; a should-not-trigger near miss) and at least eight trigger queries, half false. Expectations are checkable statements about the files produced (for example 'provenance.tasks.C1.minutes_each.source names the notes file and question F2'), taken from the fixtures' real values.
- Every file an eval case lists is under that skill's evals/files/. Notes files used from the fixtures are byte-for-byte copies; the modified ones (missing answer, disagreement) are new invented files. Nothing in them names a real company or person.
- tests/test_partner_kit_skills.py (standard library only, written so that both 'python3 -m unittest discover -s tests' and 'python3 -m unittest tests.test_partner_kit_skills' run it) checks, for every skill folder under partner-kit/plugins/twin-consultant/skills/: the same name, description, frontmatter-key and body-length rules tests/test_kit_structure.py applies to kit skills (reuse its functions, do not copy them); description under 200 characters; both eval files valid with the minimum case counts above when the skill is one of these two; each trigger file has at least four true and four false; every eval file path exists; each fixture copy under evals/files/ equals its source under engagements/ byte for byte; every question id and every field path a SKILL.md or an expectation mentions exists in the interview guide or the catalogue; the banned spoken words are absent from SKILL.md; and every repo path a SKILL.md names inside the plugin exists. It must pass with only these two skills present and keep passing when later cards add more skills.
- Do not run skill-creator or any model-graded eval loop, and do not claim the evals pass: each SKILL.md's folder gets no status claim, and the report says plainly 'evals written, not run'. Do not edit the plugin README (another card owns it).
- python3 -m unittest discover -s tests passes. The report lists, per skill: the description text, the body line count, the eval cases by id with one line each, any decision you had to make that this card did not, and the sentence from the Claude Code skills page you relied on.
